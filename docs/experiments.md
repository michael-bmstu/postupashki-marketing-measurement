# Attribution ≠ Incrementality: дизайн экспериментов (Задача 7)

«После поста продажи выросли с 9 до 68 в день» — это факт. «Пост дал +59» — гипотеза: в те же дни действовали
скидка −35%, выходные, дедлайны стажировок и pull-forward (кто купил бы позже — купил сейчас).

## Что можно оценить уже сейчас (и почему это не каузально)

`src/uplift.py`: факт заказов в волне − ожидание по обычным дням (медиана × индекс дня недели), интервал —
бутстрап обычных дней. Результат: W1 +103 [84; 119], W2 +55 [36; 71], W3 +97 [82; 107] заказов за 3 дня.
Это **верхняя граница** эффекта: контроля нет, а «обычные дни» — не то же самое, что «те же дни без поста».
Неделя после W1: −6 заказов к базе (pull-forward), после W2: +25 (хвост запуска).

## Что применимо в Telegram-канале (нельзя показать разным подписчикам разные посты)

| Дизайн | Как реализовать у Поступашек | Что измеряет | Стоимость |
|---|---|---|---|
| **Promo-code holdout** | Промокод из поста даёт скидку; случайная половина обратившихся к менеджеру получает ту же скидку без кода (или код «не работает» → менеджер предлагает обычную цену). Сравниваем конверсию лид→оплата и средний чек | инкрементальность **скидки** (не поста) | ~0 ₽, нужна дисциплина менеджера |
| **Staggered rollout по тематическим каналам** | У бизнеса есть суб-каналы (@analytic_postypashki, @postypashki_ml, @backend_postypashki, @algoses_postypashki). Продающий пост выходит в случайной половине каналов в неделю 1, в остальных — в неделю 2. DiD по заказам подписчиков (источник — deep-link суб-канала) | инкрементальность **поста** | 0 ₽, задержка 1 неделя |
| **Geo/time split внешних закупок** | 20 каналов делим случайно на 2 волны с интервалом 7–10 дней; вторая волна — контроль для первой (DiD), первая — для второй | инкрементальность **внешних размещений** | не увеличивает бюджет |
| **Interrupted time series** | Дневные заказы до/после поста с контролем дня недели и календаря; нужно ≥ 8–10 недель без пересекающихся событий | эффект одиночного события | 0 ₽, слабая мощность на 38 днях |
| **Synthetic control** | Контрольный ряд из продуктов, которых пост не касался (например, математика во время распродажи СТАРТ) | эффект по линейке | 0 ₽, зависит от «чистоты» контроля |
| **A/B креативов** | Два креатива в одной кампании → два placement_id, один канал, чередование по дням | какой оффер работает | 0 ₽ |

Рекомендуемый первый эксперимент: **promo-code holdout** на следующей распродаже — он отвечает на главный денежный
вопрос «нужна ли скидка −35%, если дедлайн Т-Банка продаёт по полной цене».

## Мощность (из `experiment_power.csv`)

При базовой конверсии лид→оплата 10% и ожидаемом эффекте +30% нужно ~885 лидов на группу; при 60 лидах/день это
≈ 30 дней (или 2 распродажи). При эффекте +50% — 341 на группу (~11 дней). Поэтому holdout запускается на
волне, а не на обычных днях, и совмещается с тестом глубины скидки (−15% vs −35%).

## Как считать ROMI_inc

```
ROMI_inc = (incremental_orders × avg_margin_per_order − cost) / cost
incremental_orders = (CR_test − CR_control) × leads_test          — для holdout
                   = DiD-оценка                                    — для staggered / geo split
```
Отчёт по кампании: ROMI_attr и ROMI_inc рядом; если ROMI_attr ≫ ROMI_inc — канал «собирает» органику.
